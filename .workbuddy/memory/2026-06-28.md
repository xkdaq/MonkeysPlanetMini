# 2026-06-28 工作记录

## 提取接口加密key到公共配置文件

### 背景
小程序项目中，接口加密密钥（AES_KEY, AES_IV, SIGN_KEY）和 BASE_URL 硬编码在多个文件中：
- `utils/crypto.js` - AES_KEY, AES_IV, SIGN_KEY
- `utils/request.js` - BASE_URL
- `utils/article-api.js` - BASE_URL + 重复的AES密钥（Base64编码）
- `utils/material-api.js` - BASE_URL + 重复的AES密钥（Base64编码）

### 改动

1. **新建 `utils/config.js`** - 集中存放所有敏感配置：
   - BASE_URL
   - AES_KEY / AES_IV
   - SIGN_KEY

2. **新建 `.gitignore`** - 忽略 `utils/config.js`

3. **更新 `utils/crypto.js`** - 从 config.js import 密钥

4. **更新 `utils/request.js`** - 从 config.js import BASE_URL

5. **更新 `utils/article-api.js`** - 从 config.js import BASE_URL + AES_KEY/AES_IV，移除重复的 Base64 编码密钥和 decodeBase64 函数

6. **更新 `utils/material-api.js`** - 同上

### 注意
- `API_VERSION`（article-api.js 的 '10'、material-api.js 的 '8'）因值不同，保留在原文件中未提取
- article-api.js 的 `API_VERSION` 被 pages/setting/setting.js 引用，保持不变

### 重要发现：两个不同的 AES_IV
原始代码中 `crypto.js` 和 `article-api.js`/`material-api.js` 使用了**不同的 AES_IV**：
- `crypto.js` 的 `AES_IV = 'K5i9TbRSthzyaQ5H'`（用于 request.js 的考试/练习/用户接口）
- Base64 解码后 article-api 实际用的是 `'K5i9TbRSthzaQ5Hm'`（用于文章/网盘/首页接口）

因此在 `config.js` 中分别定义为 `AES_IV` 和 `AES_IV_ARTICLE`，各自的引用文件导入对应的值。
